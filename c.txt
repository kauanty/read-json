

Já tentei capturar o PDF via `context.on("response", ...)` e confirmei com debug que o listener funciona, mas nenhum evento de resposta chega quando o PDF real é renderizado no popup — provavelmente porque o Chromium está processando a resposta através do visualizador PDF nativo (PDFium), que intercepta o conteúdo antes dele virar um evento de rede visível ao Playwright.

Preciso mudar a estratégia para **interceptação de rota (`route`)**, que atua numa camada anterior à renderização e deve conseguir capturar o binário antes do navegador "engolir" a resposta no visualizador.

Implemente o seguinte, substituindo a lógica atual de captura via `response`:

```python
pdf_bytes_capturados = None

def interceptar_rota_pdf(route):
    nonlocal pdf_bytes_capturados
    url = route.request.url.lower()
    if "showjasperreportpdfservlet" in url or route.request.resource_type == "document":
        try:
            response = route.fetch()
            content_type = response.headers.get("content-type", "").lower()
            corpo = response.body()
            if "application/pdf" in content_type or corpo.startswith(b"%PDF"):
                pdf_bytes_capturados = corpo
                print(f"[SUCESSO ROTA] PDF capturado via interceptação de rota: {url[:120]}...")
            route.fulfill(response=response)
        except Exception as e:
            print(f"[ERRO ROTA] Falha ao interceptar: {e}")
            route.continue_()
    else:
        route.continue_()

# Registrar a rota no CONTEXT inteiro, ANTES do clique
context.route("**/*", interceptar_rota_pdf)
```

Depois de registrar essa rota (antes do clique em "Exportar Imagens"), mantenha o restante do fluxo de clique/detecção de popup como está. Ao final, adicione `context.unroute("**/*", interceptar_rota_pdf)` na limpeza, junto com a remoção do listener de response existente (pode manter o response listener como fallback secundário, não precisa remover).
