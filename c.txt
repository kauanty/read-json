Nos logs da execução, o método de fallback (listener page.on("response") / context.on("response") filtrando por PDF/URL do showjasperreportpdfservlet) capturou corretamente o binário do PDF ("Binário do PDF capturado via evento de rede"). Porém, o método "principal" (fazer uma requisição manual separada com context.request.get(url_do_frame)) falhou e retornou o frameset HTML de erro do Oracle ADF (_AdfWindowOpenError), pois esse servidor valida que a requisição venha de uma navegação real de frame dentro da sessão (referer, viewstate, nome da janela _afrWindowId), e uma requisição solta via context.request.get não carrega esse contexto.

Preciso que você refatore a lógica para:

Remover completamente a tentativa de requisição manual via context.request.get() — ela sempre vai falhar nesse sistema ADF.
Usar exclusivamente o listener de rede como método principal (não mais como fallback): registre page.on("response") (ou no context, cobrindo todas as páginas/popups) antes de clicar em "Exportar Imagens", filtrando por content-type: application/pdf OU por URL contendo showjasperreportpdfservlet.
Ao capturar essa resposta, validar o conteúdo com response.body().startswith(b"%PDF") antes de salvar, para garantir que não é HTML de erro disfarçado.
Salvar o binário validado direto em disco, sem nenhuma etapa intermediária de extrair src de frame e refazer requisição.
Adicionar um timeout generoso de espera pelo evento de resposta (documentos de até 600 páginas podem demorar para o servidor gerar), com uma mensagem clara no console se o timeout expirar sem captura.

Mantenha absolutamente todo o restante do fluxo (login, verificação por e-mail, seleção de agência/transações) inalterado — o ajuste é só nessa etapa final de captura do PDF.
